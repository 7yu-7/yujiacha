## 五、killed 的缺陷（实测发现并修复）

### 缺陷 1：SPA 通配路由吞掉静态资源 → Web 端与后台全站白屏

**现象**：浏览器控制台报 `SyntaxError: Unexpected token '<'`，Web 端与后台页面文本量为 0。

**根因**：`/web/*`、`/admin/*`、`/mini/*` 前端路由回退的正则（`^/web/.*/?$`）
同样匹配 `/web/app.js`，导致 JS 请求先命中路由、返回了 `index.html`。

**修复**（`server/src/lib/http.js`）：静态资源优先于 SPA fallback ——
带文件扩展名的请求与未命中路由的请求都先尝试静态文件；`/api/*` 永不参与静态匹配。
同时把 `serveStatic` 的前缀判断改为「等于前缀或以 前缀/ 开头」，避免 `/web` 误匹配 `/website`。

**验证**：11 个静态资源全部返回正确 `Content-Type` 与响应体；重测后 Web 端行情页文本 4,099 字，控制台错误 **0**。

### 缺陷 2：价格序列日环比系统性同向（涨 32 / 跌 2）

**现象**：全国 34 省在多数日期同向涨跌，不符合真实市场分化特征。

**根因**：两层因素叠加 ——
① 市场级独立噪声在聚合到省均价时被平均掉，日环比失真；
② 周内因子相邻日比值达 1.3%，形成对所有省份统一的系统性抬升。

**修复**（`server/scripts/seed.js`）：
① 引入**品种 × 省份 × 日期**的共享冲击——
同省份内各市场对同一品种同步（产地集货价统一），不同省份相互独立（区域供需差异）；
② 把 `DOW_FACTOR` 相邻日比值收敛至 ≈1，让日环比由供需冲击主导。

**验证**：连续三日实测 涨17/跌16、涨22/跌11、涨12/跌22，分化自然。

### 缺陷 3：省份简称与拼音无法查询

**现象**：`/api/provinces/上海` 报「未知省份」；关注「上海 草鱼」查不到价格。

**修复**：新增 `normalizeProvince()`，把简称 / 拼音 / 别名统一归一为字典中的规范全称，
并在品种列表、详情、关注订阅等入口统一应用；展示层用 `provinceShort()` 反向输出简称。

**验证**：`上海` → `上海市`，报价 50.53 元，档位「低位」。

### 缺陷 4：F2 搜不到拼音首字母与部分别名

**现象**：`jyx` 无结果；`虾姑` 无结果。

**根因**：品种字典缺少 `pyx` 拼音变体字段；原「虾姑」未登记为别名（已并入「皮皮虾」品类）。

**修复**：为每个品种补充 `pyx` 拼音变体（如 `jiyu`/`jyx`）；补全别名（虾姑、花甲、胖头、乌贼等）；
搜索评分增加「别名精确匹配 92 分」「拼音全拼精确 76 分」两档。

**验证**：`jyx`→鲫鱼、`虾姑`→皮皮虾、`胖头`→鲢鱼。

## 六、技术栈偏离说明

PRD 3.2 / 3.3 指定 **Spring Boot（Java）+ UniApp + Vue3 + MySQL + Docker**。
本机实测环境为 **Java 8（无 Maven）、无 Docker、MySQL 5.7 已装、Node 22 可用**，
无法编译运行 Spring Boot。

本交付以 **Node 22 实现后端**，严格保持与 PRD 一致的接口契约：

- API 路径、字段名、响应结构、JWT 鉴权、四端权限分级全部按 PRD 设计；
- 数据库直连 PRD 指定的 `fish_price.price_daily`（PRD 规定的 12 个业务字段全部对齐，
  另加 `province_code` 支撑省级聚合索引）；
- **前端四端与数据库无需改动**即可迁移到 Spring Boot 实现。
